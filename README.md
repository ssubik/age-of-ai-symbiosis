# Age of AI

### 🌍 Playable in 🇺🇸 English · 🇧🇷 Português · 🇪🇸 Español

A **browser-based multiplayer real-time strategy (RTS)** game inspired by the classics of the genre (Age of Empires / Age of Mythology): resource gathering, base building, advancing through the ages, training units, and combat. All content is original — art and soundtrack generated by AI, with custom code and balancing. An **open source** project, made for fun with the help of AI.

🎮 **Play now:** **[playageofai.com](https://playageofai.com)**
*(live demo — may be offline when the server isn't running)*

> Runs 100% in the browser, on an isometric 2D Canvas. No downloads, no plugins.

🌍 **Languages:** the whole game — menus, in-game HUD, and messages — is available in **English, Portuguese, and Spanish**. It's auto-detected by your region and can be switched anytime from the in-game Options menu (the gear icon).

## Requirements

- Node.js **20+**
- npm 10+

## Running locally

```bash
npm install

# Terminal 1 — server (WebSocket on port 8080)
npm run dev:server

# Terminal 2 — client (Vite on port 5199)
npm run dev:client
```

Windows shortcut: double-click **`iniciar.bat`** — it installs dependencies (first time), starts the server and client, and opens the game in your browser.

Open `http://localhost:5199` in **two or more tabs/machines** (2 players minimum) — or play solo against a **bot** (add an AI opponent in the room). Create a room, mark yourself "Ready", and the host starts the match.

## Hosting over the internet

You can expose the game publicly with a Cloudflare Tunnel (HTTPS, no need to open a port on your router). There are two ways:

- **Quick (temporary link):** double-click **`jogar-online.bat`** → generates a `https://…trycloudflare.com` link (changes each run).
- **Fixed domain (production mode):** run **`configurar-dominio.bat`** once, then use **`jogar-online-fixo.bat`** → serves the pre-built game on your own domain, always at the same address.

Full walkthrough (including hosting on a 24/7 Android phone via Termux) in **[DEPLOY.md](DEPLOY.md)**.

## Age of Symbiosis

Hosts can switch a room to **Symbiosis**, which layers the WATT Arena model on top of the RTS. In Classic rooms none of these rules apply.

City progression now follows five levels:

1. Settlement
2. Smart District
3. Technology City
4. Symbiotic City
5. A permanent specialization chosen at the Civic Hub:
   - **Command Metropolis** unlocks attack drones, fighters, rocket launchers, and warfare against other Command cities.
   - **Space Gateway** remains protected from city warfare and gains +10 grid power from orbital infrastructure.

Levels 1–4 cannot initiate warfare and are excluded from hostile automatic targeting. The Level 5 choice costs 1,400 food and 1,400 gold and takes 70 seconds to establish.

The presentation uses a fully modern facility vocabulary while preserving the RTS economy: Modular Residences, a Civic Operations Hub, Army Basecamp, Autonomous Weapons Lab, Mobility Command, Defense Engineering Lab, Trade and Logistics Center, Food Technology Center, Materials Depot, Mineral Processing Center, Sensor Defense Tower, Modular Protection Walls, Hydroponic Farms, and a River Logistics Terminal. Active sites progressively fill with human builders, humanoid installers and masons, a heavy AI builder, material rover, survey drone, and autonomous crane.

- **Robots and drones that build.** The Robotics Workshop trains Builder Robots (build/repair 1.8× a villager, cannot gather) and Construction Drones (fly over water and terrain, build 1.25×). Bots use them too.
- **Air and rocket attacks.** The same workshop unlocks Attack Drones (fast harassment), Autonomous Fighters (heavy air strike), and Rocket Launchers (slow long-range ground artillery). They draw grid power and remain fully server-authoritative.
- **A power grid.** Solar Arrays (+4) and Wind Turbines (+6, Feudal) add supply; the Town Center gives a base of 2. Each robot or drone draws 1. When draw exceeds supply, automation slows proportionally (floor 30%) — shown as cyan or coral energy-flow lines on the map and ⚡ draw/supply in the HUD.
- **ELON standing.** Non-transferable contribution points (Energy, Labor, Obligation, Need). Not currency.
- **Match ledger.** Every ELON event becomes a transaction in a deterministic SHA-256 hash chain (Merkle tx roots) sealed every 5 s by the authoritative server. Completed facilities carry a provenance hash, and the live ledger is shown in-game.
- **On-chain anchoring.** When a match ends, the archive hash and ledger head may be committed to `contracts/MatchCommitmentRegistry.sol` (`commitWithLedger`) when blockchain support is explicitly enabled. Players see the actual disabled, local, submitted, confirmed, or failed status on the result screen.

The trust boundary is deliberately narrow:

```text
player intents → authoritative server → live state + deterministic match ledger
                                           │
                                           └─ match ends → canonical archive + SHA-256
                                                                    │
                                                                    └─ optional hash commitment
```

The chain is a provenance layer, not a game server: it never validates commands, stores ordinary gameplay actions, controls resources or victory, or turns ELON into a token. A chain outage cannot change or invalidate the match result.

The UI follows the WATT Arena design language (navy plane, cyan/mint signals, flat 1px panels, Space Grotesk + JetBrains Mono).

### Local chain (optional)

Requires [Foundry](https://book.getfoundry.sh/).

```bash
npm run chain:node                      # terminal 1: Anvil on :8545
npm run chain:build && npm run chain:deploy   # writes contracts/deployment.json
BLOCKCHAIN_ENABLED=true npm run dev:server
```

Without `BLOCKCHAIN_ENABLED=true` the ledger still runs and is archived to `archives/`, but nothing is sent to a chain. The deploy script refuses any chain other than Anvil (31337) because it uses the node's unlocked dev account. No wallet, token, or IPFS provider is involved.

## Developer commands (testing only)

To skip the long climb while testing, allow your own browser to use chat commands on **your local server**:

1. In any match, type `/whoami` in chat — only you see the reply with your browser ID.
2. Restart the server with that ID: `DEV_PLAYERS=<your id> npm run dev:server` (comma-separate several IDs).
3. In a match, type `/perfectbase` for an instant level-5 showcase city with every factory, full resources/ELON, designers, robots and a complete strike force. Smaller tools remain available: `/age`, `/res 5000`, `/build`, and `/power 50`.

Replies are private and other players never see the commands; browsers not in `DEV_PLAYERS` just send them as chat. A match where any command was used is labeled **Dev match** in Campaigns, Stewardship and the result screen, and is archived locally but never committed on-chain. Never set `DEV_PLAYERS` on a public server.

## Architecture

```
shared/   Shared contract (pure TypeScript, no dependencies)
          ├─ types.ts      — entity and snapshot types
          ├─ constants.ts  — balancing (costs, HP, speeds, map, ticks)
          └─ protocol.ts   — ClientMessage/ServerMessage messages (JSON over WebSocket)

server/   Node.js + TypeScript + ws backend — AUTHORITATIVE SERVER
          ├─ HTTP: serves the built client (client/dist) in production
          ├─ Lobby: rooms, ready-check, chat, host migration
          └─ Simulation: 10 ticks/s loop, A* pathfinding,
             state machines (gather → drop-off, building, combat),
             all commands validated on the server

client/   Vite + TypeScript + Canvas 2D frontend (dimetric isometric 2:1)
          ├─ DOM screens: name → lobby → room → game → game over
          ├─ Sprite rendering (AI-generated art) + interpolation between snapshots
          └─ HUD: resources, population, minimap, selection and action panels
```

### Technical decisions

- **WebSocket (`ws`)** for real-time bidirectional communication in the browser.
- **Authoritative server**: the client only sends *intents* (`move`, `gather`, `build`, `train`, `attack`…); all simulation and validation happen on the server — a modified client can't affect the game state.
- **Full snapshots at 5 Hz** with visual interpolation: simple, robust (a dropped message can't corrupt state), and sufficient for the match size.
- **Monorepo with a `shared` package**: a single place defines the protocol and balancing; server and client never diverge silently.

## How to play

| Action | Control |
|---|---|
| Select | Left click; drag from a unit for box selection (Shift adds) |
| Contextual command | Right click (move, gather, attack, build) |
| Camera | Click-drag empty terrain, screen-edge scroll, middle-button drag, or WASD / arrows |
| Center on Town Center | H |
| Options (volume, resolution, language) | gear icon in the corner |
| Chat | Enter |
| Cancel selection/placement | Esc |

- **Resources**: food, wood, gold, stone — villagers gather and drop them off at the Town Center.
- **Ages**: advance by constructing buildings and gathering resources, unlocking new units and structures.
- **Victory**: destroy all enemy Town Centers.

### Gameplay preservation contract

The battlefield remains the game: it fills the screen, pans like the original RTS, and keeps resources, selection, commands, construction actions, and the minimap at the edges instead of replacing the map with dashboard pages. In Symbiosis rooms, selecting either human villagers or builder robots/drones opens the same construction palette. Place a building, then right-click it with one or more builders selected; every selected human or robotic builder works through the authoritative simulation. Robots build faster but cannot gather resources, so humans remain essential to the economy.
